# リバーシ 設計書

- 日付: 2026-09-27
- 対象: `kh55/creator-world-games`（https://browser-games.creator-world.net）
- 追加先: `src/games/reversi/`、`tests/e2e/games/reversi.spec.ts`

## 1. 目的と成功条件

### 決定事項（ユーザー確認済み）

| 項目 | 決定 |
|---|---|
| 対戦形式 | CPU 対戦（1 人用）。先手はプレイヤー（黒）、CPU は白 |
| CPU の強さ | 1 段階。マス価値表を使った 2 手読み |
| スコア | 勝ったときの黒の石数（最大 64）。負け・引き分けは 0 |
| 盤面の作り | 64 マスのボタン（もぐらたたきと同じ DOM 方式。canvas は使わない） |

### 成功条件

1. `/games/reversi/` で、PC（クリック・キーボード）とスマホ（タップ）から標準ルールで CPU と最後まで対局できる。
2. トップのカード・サイトマップに自動で載り、BEST（ハイスコア）が保存される。
3. GA4 に `game_start`（最初の着手時）と `game_over`（終局時、`score` 付き）が 1 局につき 1 回ずつ届く。
4. 既存の制約（外部通信なし・CSP 違反なし・`innerHTML` 不使用・広告は解説の後だけ）を満たし、既存の単体テスト・E2E がすべて通る。

## 2. ルール

- 8×8。初期配置は中央 4 マス（d4・e5 が白、d5・e4 が黒。座標は左上 a1、x が列 a〜h、y が行 1〜8）。
- 置いたマスから縦・横・斜めの 8 方向に、連続した相手の石の先に自分の石があれば、その間の相手の石をすべて裏返す。1 枚も裏返せないマスには置けない。
- 手番の側に置けるマスがなければパス。両者とも置けなければ終局（盤が埋まった場合を含む）。
- 終局時に石の多いほうの勝ち。同数は引き分け。

## 3. ロジック（`src/games/reversi/logic.ts`）

DOM を使わない純粋な関数だけを置く。盤面は `Cell[][]`（`board[y][x]`、`Cell = 0 | 1 | 2`、0=空・1=黒・2=白）。関数は盤面を変更せず、新しい盤面を返す。

| 関数 | 役割 |
|---|---|
| `createBoard(): Board` | 初期配置の盤面 |
| `flipsFor(board, x, y, color): [number, number][]` | (x, y) に置いたとき裏返る石の座標。置けない（空きでない・0 枚）なら空配列 |
| `legalMoves(board, color): [number, number][]` | 置けるマスの一覧（行優先の順） |
| `applyMove(board, x, y, color): Board` | 置いて裏返した新しい盤面。置けない手なら例外を投げずに元と同じ内容の新しい盤面を返す |
| `count(board): { black: number; white: number }` | 石の数 |
| `nextTurn(board, justMoved): Color \| null` | 次の手番。相手に置き場があれば相手、なければ（パス）直前の側、両者とも無ければ `null`（終局） |
| `chooseCpuMove(board, color, random = Math.random): [number, number] \| null` | CPU の手。置き場がなければ `null` |
| `finalScore(board): number` | 黒が白より多ければ黒の石数、それ以外は 0 |

### CPU（`chooseCpuMove`）

- 評価関数: マス価値表の合計（自分の石は加算、相手の石は減算）。価値表は一般的な 8×8 の表を使う（角 100、C 打ち −20、X 打ち −50、辺 10 前後、内側 −2〜5）。具体値は実装計画で固定する。
- 2 手読み: 各候補手について、打った後の局面で相手（プレイヤー）が最善の応手をしたときの評価値（相手に置き場がなければ打った直後の評価値）を求め、それが最大の手を選ぶ。
- 同点の手が複数あれば `random` で 1 つ選ぶ（テストでは固定の乱数を渡す）。
- 置ける角があれば必ず選ばれることをテストで保証する（角の価値が十分大きいことの確認）。

## 4. 画面と操作（`game.ts`）

### DOM

- ステージ内に、状態表示（1 行）・石数（黒 n / 白 n）・盤面（8×8 の `<button>`）・「もう一度」ボタン（終局時のみ表示）を `createElement` で作る。`innerHTML` は使わない。
- 盤面の幅は `min(92vw, 400px)` の正方形。石は CSS（円）で表示。置けるマスに小さな点、CPU が直前に打ったマスに枠を付ける。スタイルは既存ゲームと同じくインライン `style` で付ける（CSP は style の inline を許可している）。
- 各マスの `aria-label` は「<座標> <黒|白|空き>」＋置けるときは「・置ける」（例: 「d3 空き・置ける」）。
- touchbar は使わない（ボタンを追加しない）。

### 流れ

1. ページを開くと黒番（プレイヤー）から始まる。状態は「あなたの番（黒）」。
2. プレイヤーが置けるマスを押すと着手。その局の最初の着手で `api.started()` を呼ぶ。置けないマス・CPU の番・終局後の盤面クリックは何もしない。
3. CPU の番は「CPU が考えています…」を表示し、`api.loop` で約 0.5 秒数えてから `chooseCpuMove` の手を打つ（タブ非表示中は止まり、ページ離脱時は runner が止める）。
4. パスは自動で処理し、状態に「あなたはパスです」「CPU はパスしました」を表示する。プレイヤーがパスのときは、少し待って CPU が続けて打つ。
5. 終局したら `api.submitScore(finalScore(board))` を 1 回だけ呼び、状態に「あなたの勝ち！ 42 対 22」「あなたの負け… 20 対 44」「引き分け 32 対 32」を表示し、「もう一度」ボタンを出す。
6. リトライ: 「もう一度」ボタン、または終局後の `api.input.onStart`（盤面のタップ・Enter）で新しい局を始める。プレイ中の `onStart` は無視する。
7. SCORE 表示（`api.setScore`）はプレイ中は黒の石数、終局後は `finalScore`。

### キーボード

- Tab でマスに移動し、Enter / Space で置く。
- `engine/input.ts` はステージ内のボタンで押された Enter / Space の既定動作を止めるため、ボタンの click が起きない。各マスのボタンに `keydown` リスナーを付け、Enter / Space で直接着手処理を呼ぶ（ボタンのリスナーが window のリスナーより先に動く）。エンジンは変更しない。
- 終局後の「もう一度」ボタンも同じく `keydown` で Enter / Space を処理する。

## 6. テスト

- 単体（`logic.test.ts`）: 初期配置で黒の合法手が 4 つ（d3・c4・f5・e6）／8 方向の裏返し／盤端で止まる／0 枚のマスは置けない／`applyMove` が元の盤面を変えない／パス（`nextTurn` が直前の側を返す）／終局（`null`）／角が取れるとき CPU は角を選ぶ／置き場がなければ `chooseCpuMove` は `null`／`finalScore` の勝ち・負け・引き分け。
- E2E（`reversi.spec.ts`）: 64 マスと置けるマス 4 つが表示される／置けるマスをクリックすると `game_start` が 1 回送られ、CPU が打ち返して白の石数が変わる／Tab でマスに移動し Enter で置ける。外部通信ゼロ・CSP 違反なし・JS エラーなし・パンくず・戻るは既存の `site.spec.ts` が自動で対象にする。
- 終局までの E2E は CPU の乱数で手順が固定できないため作らない。終局判定とスコアは単体テストで保証する。
